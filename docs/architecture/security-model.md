# 보안 모델

## 위협 모델

### 가장 큰 위협
사용자가 우리 `.exe`를 받아서 코드를 변조 → 우리 SaaS를 거치지 않고 자기가 별도 발급받은 우리말샘 API 키로 직접 호출.

**결과**:
- 우리 공유 캐시 효과 사라짐
- 사용 통계 수집 안 됨
- 1년 후 유료화 lock 무용
- "남 좋은 일"

### 다른 위협 (이번 모델 범위 밖)
- 사용자가 처음부터 자기 클라이언트를 작성해서 우리말샘 직접 호출 — 우리 자산 도용 아님 (그 사용자의 자기 노력)
- 정통한 OWASP top 10 — Next.js + Clerk + Drizzle 조합으로 자동 방어

## 3중 방어 레이어

```
┌────────────────────────────────────────────────┐
│ Layer 1: Electron asar 무결성 (electronFuses)  │
│  → 변조된 asar → 앱 자체 실행 거부             │
└────────────────────────────────────────────────┘
                       ↓ 우회한 경우
┌────────────────────────────────────────────────┐
│ Layer 2: JavaScript 난독화                     │
│  → 코드 분석/수정 비용 시간 → 일 단위           │
└────────────────────────────────────────────────┘
                       ↓ 우회한 경우
┌────────────────────────────────────────────────┐
│ Layer 3: SaaS 측 binary hash 검증              │
│  → 매 요청마다 X-Client-Hash 매치 확인          │
│  → official_binaries 테이블 화이트리스트         │
└────────────────────────────────────────────────┘
```

각 레이어를 모두 우회하려면 **결정한 공격자의 수십 시간 투자** 필요. 일반 사용자 99% 차단.

## 인증 흐름 (변경 후)

```
[로컬 HUD .exe 시작]
   ↓ 자기 자신 SHA-256 계산 (메모리에 보관)
[검색 요청]
   ↓ Authorization: Bearer hk_live_...
   ↓ X-Client-Hash: <SHA-256 hex>
[SaaS authenticate(req)]
   ↓ Bearer 헤더 있으니 verifyApiKeyFromHeader(authHeader, clientHash)
   ↓ ① clientHash 형식 검증 (64자 hex)
   ↓ ② isOfficialBinary(clientHash) → Redis or DB 조회
       ↳ 매치 실패 → null (인증 거부)
   ↓ ③ 키 hash 매치 + status='approved'
   ↓ 통과: User 반환
```

## official_binaries 테이블

| 컬럼 | 의미 |
|------|------|
| id | PK |
| version | "0.2.0" 같은 버전 문자열 |
| sha256 | 빌드된 .exe의 SHA-256 (64자 hex, UNIQUE) |
| released_at | 등록 시각 |
| notes | 릴리스 메모 (선택) |

매 빌드 후 `scripts/register-binary.mjs`로 자동 등록.

## 본질적 한계 (인정)

- **클라이언트 코드는 본질적으로 분석 가능**: 모든 데스크톱 SW의 한계 (Spotify·Slack·Notion도 동일)
- **검증 로직 자체를 우회 가능**: 결정한 공격자는 어쨌든 뚫음
- **우리말샘 API 키는 무료**: 사용자가 자기 키 발급 자체는 막을 수 없음
- **하지만 일반 사용자 99%는 차단**: 비즈니스 임팩트 충분

## 향후 강화 옵션

- EV 코드 서명 인증서 (~연 30~50만원, 매출 후)
- Native binary로 핵심 로직 이전 (Rust/C++)
- 디바이스 fingerprint 바인딩
- 검증 실패 사용자 자동 비활성화 (지금은 단순 거부)
